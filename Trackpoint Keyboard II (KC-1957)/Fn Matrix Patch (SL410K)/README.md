# KC-1957 Fn 键矩阵化改造 — 归档说明（v5.1）

**归档版本**：`v5_force_mask`（**v5.1**）
**归档日期**：2026-10-24
**固件基线**：`KC-1957_88_orig.bin`（SHA-256 见 `SHA256SUMS.txt`）
**补丁产物**：`KC-1957_88_fn7_v51.bin`（246 字节 / 10 区域）

---

> ⚠️ **使用前必读**
>
> 1. **硬件版本**：本补丁只适用于 **V2 及以上**硬件。V1 等低版本固件布局不同，注入地址与键位表假设不成立，**不要尝试**；低版本设备需自行向持有 V2+ 固件的人索取一份 V2+ 固件。
> 2. **不要用哈希校验固件**：每台设备 Dump 出来的固件本来就不完全一样（蓝牙名称、2.4G 无线 ID 等为设备独有），原厂固件与补丁产物的 SHA-256 **都因机而异**。正确判据是**补丁脚本的前置检查**（干跑）与**验证脚本的结构性检查**。
> 3. **`--out` 必须显式指定**：不指定时会回退到输入路径，配合 `--apply` 会**覆盖你的原始固件**。

## 零、v5.1 修订（本次归档的主要变化）

做 v6（左 Ctrl 与 Fn 完全互换）改造时，需要把 v5 的 Fn 矩阵化机制逐条拆开重新验证，
顺带把两条扫描路径的行循环全部读了一遍 —— 结果发现 **v5 的 Trampoline B（2.4G 行循环）
有两处实质缺陷**。这两处都是 v5 自身的推理盲区，直到 v6 逐指令核对 2.4G 路径才暴露出来。

| 缺陷 | 现象 | v5.1 修法 |
|---|---|---|
| ① 2.4G 屏蔽失效 | 2.4G 逐位测试用的是**寄存器 r0**（`0x4126C: tst.w r0, ip`），而 v5 只清 `local_84[r4]` → 2.4G 模式下 r12c4 根本没被屏蔽 | 同时清 r0 与 `local_84[r4]` 的 bit4 |
| ② 整行丢键 | `cmp/tst/movs` 改写 NZCV，而 `0x4125E` 的 `beq` 依赖 `0x4124C` `bics` 的 Z 位 → 第 12 行的**其它按键被整行丢弃** | 返回前用 `cmp r0,#0` 复原标志位（与原 `bics` 语义一致） |

蓝牙路径不受影响 —— BT 的逐位测试读的是**数组** `local_64[row]`（`0x1E67A`），
v5 清 local_64 本来就是对的。**两条路径的行为不对称，根源就在这里。**

另更正一处文档错误：RAM 选址依据由「最高引用 `0x20004138` / 654 个地址」更正为
**精确普查实测「661 个地址、最高 `0x20003928`」**
（前者是宽松扫描把落在指令中间的半字误当成 `ldr` 造成的误报；`0x20004138` 实为 0 处引用）。
选址结论不受影响：`FN_MATRIX@0x20004800` 距真实最高引用仍有余量 3616 字节。

**改动范围**：与 v5.0 产物的差异严格限定在 trampoline B 区段 `0x050100-0x0501FF`（47 字节），
其余 3 个 trampoline、4 个钩子点、2 个掩码字节全部逐字节不变。

## 一、v5 相对 v4 的唯一变化（掩码强制修补开关）

v4 的逻辑完全保留，v5 **只放宽了「键盘掩码与预期值不符」时的中止行为**：

| 断言类别 | 地址 | 不符时的行为 |
|---|---|---|
| **hook 代码点** | `0x1E4E4` / `0x41252` / `0x411C6` / `0x1B7C0` | 仍为**硬中止**（exit 2）；仅 `--force` 可放行 |
| **键盘掩码点** | `0x1E84C` / `0x4A6B2` | `--force-mask` 可**强制修补**（按「实际值 + 位操作」，不套用原版常量） |
| 代码空洞 | `0x050000`–`0x0504xx` | **任何开关都不绕过**：必须全 `0xFF`、必须落在 `0x50000–0x60000` |
| 固件长度 / 向量表 | — | **任何开关都不绕过** |
| 新变量选址窗口 | `0x20004800`–`0x20004900` | 必须无任何 pc 相对字面量引用（v5.1 新增的启动时现场复核） |

## 三、复现步骤

```bash
# 1) 打补丁（--out 必须显式指定，否则会覆盖输入固件）
python fn_matrix_patch3.py KC-1957_88_orig.bin --out KC-1957_88_fn7_v51.bin --apply

# 2) 独立验证（45 项）
python verify_v51.py KC-1957_88_orig.bin KC-1957_88_fn7_v51.bin
```

从归档副本重跑补丁 → 产物 SHA-256 与 `KC-1957_88_fn7_v51.bin` **完全一致**（可复现）。
