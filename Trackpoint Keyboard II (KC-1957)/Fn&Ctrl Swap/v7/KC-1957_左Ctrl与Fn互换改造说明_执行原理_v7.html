KC-1957（nRF52832）左 Ctrl 与 Fn 完全互换改造 · P0.6 去抖（v7）

一句话结论：v7 = v6 + P0.6 去抖。在 v6「左 Ctrl 与 Fn 完全互换」基础上，把 P0.6 发 Left Ctrl 的判定由「原始 P0.IN bit6」改为「去抖后的 E0F2」，消除机械按键抖动导致的 Left Ctrl 误触发。差异严格限定在 trampoline C / E 两段（共 50 字节），其余与 v6 逐字节一致。

一、为什么需要去抖

机械按键在按下/松开的瞬间会产生数十毫秒抖动。v6 中 P0.6 发 Left Ctrl 直接读原始电平（P0.IN bit6），一次按键可能被识别为多次「按下→松开→按下」，导致 Left Ctrl 粘连、组合键误判。

二、核心机制：复用去抖状态机的输出 E0F2

三、两处改动（v6 → v7）

3.1 Trampoline C（2.4G P0.6 判定 / 伪键）

; v6：读原始 P0.IN bit6
0x50208  4F F0 00 40  mov.w r0, #0x50000000
0x5020C  D0 F8 10 05  ldr.w r0, [r0, #0x510]   ; P0.IN
0x50210  40 07        lsls  r0, r0, #0x19     ; bit6 → bit31
0x50212  04 D5        bpl   .pressed

; v7：读去抖 E0F2
0x50208  DF F8 18 00  ldr.w r0, [pc, #0x18]   ; r0 = &E0F2
0x5020C  00 78        ldrb  r0, [r0]          ; r0 = E0F2
0x5020E  01 28        cmp   r0, #1            ; 去抖后按下？
0x50210  04 D1        bne   .up

3.2 Trampoline E（蓝牙 HID 修饰位）

; v6：读原始 P0.IN bit6
0x50404  4F F0 00 40  mov.w r0, #0x50000000
0x50408  D0 F8 10 05  ldr.w r0, [r0, #0x510]   ; P0.IN
0x5040C  40 07        lsls  r0, r0, #0x19
0x5040E  04 D5        bpl   .pressed

; v7：读去抖 E0F2
0x50404  DF F8 10 00  ldr.w r0, [pc, #0x10]   ; r0 = &E0F2
0x50408  00 78        ldrb  r0, [r0]          ; r0 = E0F2
0x5040A  01 28        cmp   r0, #1            ; 去抖后按下？
0x5040C  01 D1        bne   .fin

四、Trampoline C / E 完整代码（v7，真实二进制）

Trampoline C（@0x50200，40 字节）

0x50200  DF F8 1C 00  ldr.w r0, [pc, #0x1c]   ; r0 = &E0F
0x50204  00 78        ldrb  r0, [r0]          ; r0 = E0F（矩阵 Fn）
0x50206  07 46        mov   r7, r0            ; r7 = 矩阵 Fn
0x50208  DF F8 18 00  ldr.w r0, [pc, #0x18]   ; r0 = &E0F2
0x5020C  00 78        ldrb  r0, [r0]          ; r0 = E0F2（去抖后 P0.6）
0x5020E  01 28        cmp   r0, #1            ; 去抖后按下？
0x50210  04 D1        bne   #0x5021c          ; 否 → .up
0x50212  01 25        movs  r5, #1            ; uVar11 = 1
0x50214  E0 21        movs  r1, #0xe0         ; 伪 Left Ctrl 键
0x50216  8D F8 10 10  strb.w r1, [sp, #0x10]   ; local_98[0] = 0xE0
0x5021A  00 E0        b     #0x5021e
0x5021C  00 25        movs  r5, #0            ; .up: uVar11 = 0
0x5021E  70 47        bx    lr

Trampoline E（@0x50400，28 字节）

0x50400  00 23        movs  r3, #0
0x50402  0B 70        strb  r3, [r1]          ; *param_1 = 0
0x50404  DF F8 10 00  ldr.w r0, [pc, #0x10]   ; r0 = &E0F2
0x50408  00 78        ldrb  r0, [r0]          ; r0 = E0F2（去抖后 P0.6）
0x5040A  01 28        cmp   r0, #1            ; 去抖后按下？

0x50410  0B 70        strb  r3, [r1]          ; *param_1 = 1（Left Ctrl 位0）
0x50412  00 23        movs  r3, #0            ; 返回时 r3=0
0x50414  70 47        bx    lr

五、预期运行结果

物理键位行为说明
矩阵 r12c4发 Left Ctrl与 v6 一致
矩阵 r15c0充当 Fn（本身不发码）与 v6 一致
GPIO P0.6发 Left Ctrlv7 新增去抖：读 E0F2 而非原始 P0.IN

改动范围：274 字节 / 18 区域，全部落在 0x50000–0x60000 擦除空洞，向量表 Reset_Handler（0x00000A81）不变。v7 相对 v6 仅差 trampoline C / E 两段（共 50 字节）。独立验证脚本 verify_v7.py 共 89 项检查全部通过。固件哈希：orig = 57df656c…、v7 = 3f68e61b…。

六、已知边界（v6 遗留，v7 未涉及）

  • r12c4 的 Left Ctrl 仅非 Fn 层生效：Fn 层键码表 0x2CC78 未改，按住 Fn 再按 r12c4 走 Fn 层原映射，不是 Left Ctrl。
