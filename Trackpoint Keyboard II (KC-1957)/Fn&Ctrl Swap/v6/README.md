# v6 —— 左 Ctrl 与 Fn 完全互换改造

KC-1957（nRF52832）键盘固件的**键位互换**补丁。
本版**直接在原始固件上打补丁**，不依赖 v5 或任何中间版本产物。

> ⚠️ **使用前必读**
>
> 1. **硬件版本**：本补丁只适用于 **V2 及以上**硬件。V1 等低版本固件布局不同，注入地址与键位表假设不成立，**不要尝试**；低版本设备需自行向持有 V2+ 固件的人索取一份 V2+ 固件。
> 2. **不要用哈希校验固件**：每台设备 Dump 出来的固件本来就不完全一样（蓝牙名称、2.4G 无线 ID 等为设备独有），原厂固件与补丁产物的 SHA-256 **都因机而异**。正确判据是**补丁脚本的前置检查**（干跑）与**验证脚本的结构性检查**。
> 3. **`--out` 必须显式指定**：不指定时会回退到输入路径，配合 `--apply` 会**覆盖你的原始固件**。

## 改造目标

| 物理位置 | 改造前 | 改造后 |
|---|---|---|
| 矩阵 r15c0（原 Left Ctrl 键位） | 发 Left Ctrl | **充当 Fn**（激活 Fn 层，本身不发码） |
| 矩阵 r12c4（原空槽） | 空槽 | **发 Left Ctrl** |
| GPIO P0.6（原 Fn 键位，低有效） | Fn | **发 Left Ctrl**，不再参与任何 Fn 语义 |

## 补丁点一览

* 数据补丁 7 字节 + 1 个 Thumb 字面量池槽（`0x1B8A0`：P0.6 去抖状态机的 E0F 池槽改指 `E0F2`）
* 代码钩子 5 个：`0x1E4E4` / `0x41252` / `0x411C6` / `0x1EB74` / `0x23A76`
* Trampoline 落在 `0x050000-0x05041B`（限定空洞区 `0x50000-0x60000`，原为全 `0xFF`）

核心手法：**把 `E0F`（Fn 按下状态）整体换源为「矩阵 r15c0 按下」**——
只需隔离唯一写它的那 6 处去抖状态机引用，其余 14 处读取点全部自动跟随，
连 `2109 = E0F && D7B`（Fn 层激活）也自动变成跟手矩阵键。

## 使用

```bash
# 干跑检查
python fn_swap_patch.py KC-1957_88_orig.bin

# 正式打补丁
python fn_swap_patch.py KC-1957_88_orig.bin --out KC-1957_88_v6.bin --apply

# 独立验证
python verify_v6.py KC-1957_88_orig.bin KC-1957_88_v6.bin
```

## 注意

* 本次改造的全部结论来自**静态分析 + 反汇编复核 + 行为仿真**，**没有实机刷写验证**。
  上机前请保留 `KC-1957_88_orig.bin` 作为回滚基线。
* 变体固件若键盘掩码表取值不同，可用 `--force-mask` 按「实际值 + 位操作」强制修补
  （不套用原版常量，因此掩码表其余位不会被覆盖）。
* 补丁脚本启动时会做两项**语义自检**，不满足即中止：
  ① HOOK_A 覆盖的 `ldr r1,[pc,#imm]` 的池槽值必须等于 `ROWPIN`（保证覆盖前后 `r1` 等价）；
  ② 蓝牙/2.4G 行掩码 row15 的 bit0 必须放行 col0 —— 否则 r15c0 不参与扫描、**Fn 永不触发**。
* `r12c4` 的 Left Ctrl 只在**非 Fn 层**生效：Fn 层键码表 `0x2CC78` 未改动
  （`idx100` 仍为 `0x1C`），按住 Fn 再按 r12c4 走的是 Fn 层映射。
* 详见说明文档第七、八节（验证结论与已知限制）。
