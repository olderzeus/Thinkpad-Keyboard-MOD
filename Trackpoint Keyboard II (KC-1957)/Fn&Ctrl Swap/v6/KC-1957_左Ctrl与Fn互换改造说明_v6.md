# KC-1957（nRF52832）左 Ctrl 与 Fn 完全互换改造说明

> 补丁脚本 `fn_swap_patch.py`（v6）　独立验证脚本 `verify_v6.py`　补丁产物 `KC-1957_88_v6.bin`（274 字节 / 18 区域）
>
> **本版直接在原始固件（`KC-1957_88_orig.bin`）上打补丁**，不依赖 v5 或任何中间版本。所有 ASM 行均附**真实二进制数值**（取自最终固件，与补丁脚本逐字节一致）。
>

**改造背景：**左 Ctrl 与 Fn 完全互换，是为满足**部分用户对键位布局的使用习惯需求**——将最左下角原本的 Left Ctrl 改为充当 Fn，同时将 Fn 所释放出的位置（矩阵 r12c4 与 GPIO P0.6）改为发 Left Ctrl，使习惯该布局的用户无需改变肌肉记忆即可使用。

## 一、最终结果和逻辑

> **一句话结论：**把 *Fn 的判定源*从「P0.6 GPIO」整体换成「矩阵 r15c0」，同时把 *键位映射*对调——**r12c4 与 P0.6 发 Left Ctrl，r15c0 当 Fn 用**。
>
> 改造后固件里 **P0.6 完全不再参与 Fn 语义**：`2109 = E0F && D7B`（Fn 层激活）中的 `E0F` 已变成「矩阵 r15c0 按下」，而 P0.6 只剩下「发 Left Ctrl」这一条作用。
>

| 物理位置 | 改造前行为 | 改造后行为 | 实现方式 |
|---|---|---|---|
| 矩阵 **r12c4**（idx 100，原空槽） | 空槽，不产生任何键码 | **发 Left Ctrl（0xE0）** | 键码表改为 0xE0 + 行掩码放行 bit4 |
| GPIO **P0.6**（旧 Fn 键，低有效） | Fn（激活 Fn 层） | **发 Left Ctrl（0xE0）** | BT 侧在 HID 组装处注入修饰位；2.4G 侧把伪键 0xDF 改成 0xE0 |
| 矩阵 **r15c0**（idx 120，原 Left Ctrl） | 发 Left Ctrl（0xE0） | **充当 Fn（激活 Fn 层，本身不发码）** | 键码表改为 0x00 + 扫描行循环钩子写 `E0F` |

### 1.1　关键设计：只改一个字面量池槽

固件里 Fn 状态变量 `E0F @ 0x20001E0F` 被 **20 处** 引用，分布在 **6 个** Thumb 字面量池槽里：

| 池槽 | 引用数 | 所属函数 | 语义 | v6 处理 |
|---|---|---|---|---|
| `0x1B8A0` | 6（2 写 4 读） | `FUN_0001b75c` P0.6 去抖状态机 | **独占写** E0F | **改指 E0F2**（新变量） |
| `0x1B714` | 1（读） | `FUN_0001b494` Fn 长按检测 | 读 E0F | 不动 → 自动跟随矩阵 Fn |
| `0x1E868` | 7（读） | `FUN_0001e40c` 蓝牙扫描 | 读 E0F | 不动 → 自动跟随矩阵 Fn |
| `0x1ECD0` | 2（读） | `FUN_0001e40c` 蓝牙扫描 | 读 E0F | 不动 → 自动跟随矩阵 Fn |
| `0x020B4C` | 2（读） | `FUN_00020a0c` 键码重映射 | 读 E0F | 不动 → 自动跟随矩阵 Fn |
| `0x020FD4` | 2（读） | `FUN_00020bd8` 计算 2109 | 读 E0F | 不动 → 自动跟随矩阵 Fn |

于是：

- 唯一写入 E0F 的去抖状态机被「隔离」到新变量 `E0F2`，**P0.6 的去抖照常进行，但不再污染 E0F**；
- 14 处读取 E0F 的代码**一行都不用改**，全部自动改为跟随矩阵 Fn；
- 其中最关键的 `FUN_00020bd8`：`if ((E0F == 1) && (D7B == 1)) { *2109 = 1; }` 变成 `2109 = 矩阵Fn && D7B` —— **P0.6 不再激活 Fn 层**。

> **反向的「Fn → Left Ctrl」完全走既有通路，不新增任何代码：**
>
> 键码表里的 `0xE0` 由两条扫描路径分别交给各自的 HID 组装函数，按 `1 << (code - 0xE0)` 转成修饰位 0。
>
> **2.4G 路径（直接）**：键码表 `0x4A6FA[120]` 本来就是 `0xE0`，扫描后进入键码数组，由 2.4G 报告组装按 `0xE0 → 修饰位 0` 处理。这条通路由原始固件自证。
>
> **蓝牙路径（三表串联 + 位图双保险）**：BT 扫描遇到 `0xE0–0xE7` → 写入修饰键表 `0x20002E81` → 并入扫描键码数组 `0x20002E61` → 写入上报候选表 `0x20002E94`（`= param_1`）；另有 `DAT_0001f1c4 |= 1 << (code-0xE0)` 独立维护修饰位图。HID 组装 `FUN_00023a40` 遍历候选表，遇 `[0xE0,0xE7]` → `*param_1 |= 1 << (code-0xE0)`。两条都不需要本补丁新增代码——本补丁只需把 `KEYTBL_BT[100]` 由 `0x00` 改成 `0xE0`，即接入既有通路。
>

### 2.2　Fn 的 GPIO 逻辑（改造前）

Fn 原本在 MCU 通用输入引脚 `P0.6` 上，**低电平有效**（active-low）：

```asm
P0.IN             @0x50000510 的 bit6 == 0   ->  P0.6 按下
        |
        v
E0E @0x20001E0E   去抖计数器（FUN_0001b75c 独占维护）
        |
        v
E0F @0x20001E0F   去抖后的「Fn 按下」（FUN_0001b75c 独占写）
        |
        v
2109 @0x20002109  Fn 层激活 = E0F && D7B（FUN_00020bd8 计算，D7B = Fn 档位门控）
```

读 P0.IN bit6 的通用辅助函数是 `FUN_00025136(bit)`，全映像共 8 处调用：

| 调用点 | 所属函数 | v6 处理 |
|---|---|---|
| `0x1B774` `0x1B79C` `0x1B7AA` `0x1B7D8` | `FUN_0001b75c` P0.6 去抖状态机 | 不动（仍去抖 P0.6，结果写入 E0F2） |
| `0x1DBB8` | `FUN_0001db10`（位号来自数组，非固定 6） | 不动 |
| `0x20BDC` `0x20BF0` | `FUN_00020bd8`（Fn 按下/松开边沿检测） | 不动（继续由 P0.6 驱动 P0.6 去抖计时器） |
| `0x23D2A` | `FUN_00023d10`（读 bit31，与 Fn 无关） | 不动 |

另有两处**内联**读 P0.IN（不走 `FUN_00025136`）：

| 地址 | 所属 | 原语义 | v6 处理 |
|---|---|---|---|
| `0x1EB80` | `FUN_0001e40c` 蓝牙扫描 | 条件「P0.6 松开」≈「Fn 未按住」 | **Hook D**：改读 E0F |
| `0x411C6` | `FUN_00041180` 2.4G 扫描 | 「P0.6 按住 → 写伪 Fn 键 0xDF」，并置 r7 = Fn 保持标志 | **Hook C**：r7 改读 E0F，伪键改成 0xE0 |

### 2.3　修饰位从键码到 HID 报告的完整通路（复核补记）

「把某个键位变成 Left Ctrl」不是靠键码表一个字节就够的 —— 必须确认 `0xE0` 这个码值确实会被固件翻译成 HID 报告里的**修饰字节位 0**。逐字节追踪的结果如下（BT 与 2.4G 各一套）：

| 环节 | 蓝牙（BT） | 2.4G |
|---|---|---|
| ① 键位产生码值 | `KEYTBL_BT[100]` → `0xE0` | `KEYTBL_G[100]` → `0xE0` |
| ② 扫描阶段归类 | 命中 `0xE0–0xE7` → 写入修饰键表 `0x20002E81` | 写入键码数组 |
| ③ 并入上报候选 | `0x20002E61[]` → `0x20002E94`（`param_1`） | 直接在数组内 |
| ④ 修饰位图（独立通路） | `DAT_0001f1c4 \|= 1<<(code-0xE0)` | 无（2.4G 另有右修饰位图） |
| ⑤ HID 组装 | `FUN_00023a40`：`[0xE0,0xE7]` → `*param_1 \|= 1<<(code-0xE0)` | 2.4G 报告组装：`0xE0` → 修饰位 0 |

关键结论：**第 ⑤ 步的 `1 << (code - 0xE0)` 转译在两条路径上都存在**，所以「键码表里放 `0xE0`」这个做法是固件原生的、无需新增代码的通路。本补丁把 `KEYTBL_BT[100]` / `KEYTBL_G[100]` 由 `0x00` 改成 `0xE0`，即等于接入了这条既有通路。

> 复核补记：早期版本曾把这条通路概括成「键码表里的 0xE0 原样交给 HID 组装函数」，并以 `KEYTBL_G[120] 原本就是 0xE0` 作为「已被原始固件自证」的依据。该依据**只对 2.4G 成立**——蓝牙侧的实际链路是上表的三表串联 + 位图双保险。结论（r12c4 可作 Left Ctrl）不变，但依据已按上表更正。
>

## 三、实现逻辑架构

下面用文本（ASCII 框图 + 文字树）说明 v6 的实现架构。三泳道分别描述「Fn 判定线」「P0.6 支路」「Left Ctrl 线路」，右侧为「改动范围」面板。

```text
┌──────────────────────────────────────────────────────────────────────────┐
│                        v6 实现架构（文本示意）                              │
└──────────────────────────────────────────────────────────────────────────┘

① Fn 判定线（唯一改动点：E0F 换源）
─────────────────────────────────────────────────────────────
矩阵 r15c0（原 L-Ctrl 键位）
  键码表 idx120 → 0x00（不发码）；扫描时清掉该行位图 bit0
        │
        ▼
Trampoline A @0x1E4E4（BT） / B @0x41252（2.4G）
  判 row15 col0 → 写 E0F = 1 / 0
        │
        ▼
E0F @0x20001E0F（Fn 状态）
  14 处读取全部未改 → 自动跟随矩阵 Fn（唯一写者：Trampoline A / B）
        │
        ▼
Fn 层激活
  BT：2109 = E0F && D7B
  2.4G：r7 = E0F（Fn 门控）

③ P0.6 支路（v6 后完全退出 Fn 语义）
─────────────────────────────────────────────────────────────
GPIO P0.6（原 Fn 键位，低电平有效）
  v6 后仅剩「发 Left Ctrl」一项
        ├─ 分支①：直接读 P0.IN bit6
        │     ├→ Hook C（2.4G @0x411C6）：伪键 0xDF → 0xE0
        │     └→ Hook E（BT @0x23A76）：*param_1 |= 1
        └─ 分支②：P0.6 去抖状态机 FUN_0001b75c
              └→ v6 写入 E0F2 @0x20004800（新建，仅去抖自用）
              ⊘ v6 断开：池槽 0x1B8A0 由 E0F 改指 E0F2 → P0.6 不再写入 E0F
  E0F2 不参与任何 Fn 判定；P0.6 已完全退出 Fn 语义

② Left Ctrl 线路（两个来源，都不需要新增 HID 通路）
─────────────────────────────────────────────────────────────
矩阵 r12c4（原空槽）
  键码表 idx100 → 0xE0；行掩码放行 r12 bit4
        │
        ▼
既有 HID 修饰位通路（未改代码）
  0xE0 → 1 << (code - 0xE0) → 修饰位 bit0
        │
        ▼
HID 报告修饰字节 bit0 = Left Ctrl
  来源① r12c4 键码　来源② P0.6 注入 → 上报主机（BT / 2.4G 报告）

⊘ v6 断开标记：P0.6 去抖的池槽 0x1B8A0 由 E0F 改指 E0F2，P0.6 不再写入 E0F；
14 处读取 E0F 的代码一行未改。
```

**改动范围（面板要点）**：数据补丁 7 字节 + 1 个字面量（键码表 ×4、行掩码 ×2、池槽 ×1）；钩子 5 处（A 0x1E4E4、B 0x41252、C 0x411C6、D 0x1EB74、E 0x23A76）；Trampoline 5 个（0x50000 / 0x50100 / 0x50200 / 0x50300 / 0x50400）；合计 274 字节 / 18 区域，全部落在 0x50000–0x60000 擦除空洞（静态不可达）。

**为什么 r15c0 不发任何键码**：Fn 在这套固件里是「层」而不是「键」——它只改变其它键的映射，本身不占 HID 键码槽。所以 r15c0 的键码表条目改成 `0x00`，同时扫描钩子把该行位图的 bit0 清掉，双保险保证它不产生独立键码。

### 4.3　新增 / 复用变量

| 变量 | 地址 | 说明 |
|---|---|---|
| `E0F` | `0x20001E0F` | **复用**：由「P0.6 去抖按下」改为「矩阵 r15c0 按下」 |
| `E0F2` | `0x20004800` | **新增**：P0.6 去抖后状态，仅去抖状态机 `FUN_0001b75c` 使用 |

`E0F2` 选址依据：按函数边界精确普查 2434 个函数实测，全映像 pc 相对字面量引用的 RAM 变量共 **661 个**，最高只到 `0x20003928`；`0x20003928` 之上零引用，故取最高引用 +3616 字节处。补丁脚本启动时会**现场复核** `0x20004800-0x20004900` 窗口内引用数为 0（采用保守扫描口径，每 2 字节扫一次，会把落在指令中间的半字误当成 ldr；精确普查 661 个 vs 保守扫描 665 个，差出来的 8 个即误报，其中包括 `0x20004770`）。

## 五、代码改造逐点说明（原始代码 → Patch 后代码 → 对应 Trampoline）

每个 hook 点按 **① 原始代码**（patch 前，取自原始固件）→ **② Patch 后代码**（最终固件）→ **③ 跳转到的 Trampoline** 三段展开。所有行均附**真实二进制数值**（小端，与 fn_swap_patch.py 逐字节一致），地址为首列、二进制与代码同一行。

### 5.1　Hook A：蓝牙扫描行循环（@0x1E4E4）

#### ① 原始代码（patch 前，取自原始固件）

```asm
0x1E4E4   00 BF         nop

0x1E4E8   4A 5D         ldrb  r2, [r1, r5]      
0x1E4EA   01 21         movs  r1, #1            
0x1E4EC   01 FA 02 F0   lsl.w r0, r1, r2        
0x1E4F0   D8 49         ldr   r1, [pc, #0x360]  
0x1E4F2   10 39         subs  r1, #0x10         
0x1E4F4   08 60         str   r0, [r1]          
0x1E4F6   00 BF         nop                       
0x1E4F8   D5 48         ldr   r0, [pc, #0x354]  
0x1E4FA   D6 49         ldr   r1, [pc, #0x358]
```

蓝牙扫描函数 `FUN_0001e40c` 的行循环内。hook 点位于读取当前行 GPIO 列状态之前：`ldr r1,[pc,#0x370]` 把**行引脚表 ROWPIN(0x2CBE0)**装入 r1，随后 `ldrb r2,[r1,r5]` 读出行号 r5 各列的物理电平，`lsl.w r0,r1,r2` 把按下列换算成列位（r0 = 该行列位图 `local_64[r5]`）。调用 trampoline 时 **r0 即列位图、r5 即行号**，故 trampoline 用 `tst r0,#1` 检测 col0（bit0，即 r15c0）。

#### ② Patch 后代码（最终固件 @0x1E4E4）

```asm
0x1E4E4   31 F0 8C FD   bl    #0x50000          
0x1E4E8   4A 5D         ldrb  r2, [r1, r5]      
0x1E4EA   01 21         movs  r1, #1            
0x1E4EC   01 FA 02 F0   lsl.w r0, r1, r2        
0x1E4F0   D8 49         ldr   r1, [pc, #0x360]  
0x1E4F2   10 39         subs  r1, #0x10         
0x1E4F4   08 60         str   r0, [r1]          
0x1E4F6   00 BF         nop                       
0x1E4F8   D5 48         ldr   r0, [pc, #0x354]  
0x1E4FA   D6 49         ldr   r1, [pc, #0x358]  
0x1E4FC   08 60         str   r0, [r1]          
0x1E4FE   05 20         movs  r0, #5
```

原始 16 进制：00 BF DC 49 4A 5D 01 21 01 FA 02 F0 D8 49 10 39 08 60 00 BF D5 48 D6 49 08 60 05 20　→　Patch 后 16 进制：31 F0 8C FD 4A 5D 01 21 01 FA 02 F0 D8 49 10 39 08 60 00 BF D5 48 D6 49 08 60 05 20

原 4 字节（`nop` + `ldr r1,[pc,#0x370]`）被替换为 `bl 0x50000`。执行到此处跳入 Trampoline A；返回后 r1 已被 trampoline 还原为 ROWPIN，故紧接着的 `ldrb r2,[r1,r5]` 等后续指令与原始完全一致、对调用者透明。

#### ③ 跳转到的 Trampoline A — 蓝牙扫描行循环（@0x50000，60 字节）

蓝牙扫描行循环。调用点 r0=local_64[r5]（列位图），故 tst r0,#1 检测 r15c0。返回前把被覆盖的 r1 还原为 ROWPIN。r15c0 的 bit0 同时清掉，使其不再产生独立键码。

```asm
0x50000   0F 2D         cmp   r5, #0xf          ; 仅当扫描到 row15 才处理；其它行跳 .restore 直接返回
0x50002   12 D1         bne   #0x5002a          ; .restore 标签
0x50004   10 F0 01 0F   tst.w r0, #1            ; 检测当前行列位图 bit0（col0）= 矩阵 Fn 是否按下
0x50008   0B D0         beq   #0x50022          ; bit0=0（未按下）转 .zero 分支
0x5000A   01 22         movs  r2, #1            ; 按下：E0F = 1
0x5000C   DF F8 20 10   ldr.w r1, [pc, #0x20]   ; r1 ← 字面量池 @0x50030 = E0F(0x20001E0F)
0x50010   0A 70         strb  r2, [r1]          ; E0F = 1（矩阵 Fn 按下）
0x50012   07 A9         add   r1, sp, #0x1c     ; r1 ← local_64[15] 栈地址
0x50014   51 F8 25 20   ldr.w r2, [r1, r5, lsl #2]
0x50018   22 F0 01 02   bic   r2, r2, #1        ; 清掉 bit0，避免 r15c0 产生独立键码
0x5001C   41 F8 25 20   str.w r2, [r1, r5, lsl #2]
0x50020   03 E0         b     #0x5002a          ; 跳 .restore
0x50022   00 22         movs  r2, #0            ; .zero 分支：E0F = 0
0x50024   DF F8 0C 10   ldr.w r1, [pc, #0xc]    ; r1 ← E0F
0x50028   0A 70         strb  r2, [r1]          ; E0F = 0（矩阵 Fn 松开）
0x5002A   DF F8 0C 10   ldr.w r1, [pc, #0xc]    ; r1 ← 字面量池 @0x50038 = ROWPIN(0x2CBE0)
0x5002E   70 47         bx    lr                ; 返回扫描函数
```

字面量池：

| 地址 | 字节 | 值 | 含义 |
|---|---|---|---|
| 0x50030 | 0F 1E 00 20 | = 0x20001E0F | E0F |
| 0x50034 | 0F 1E 00 20 | = 0x20001E0F | E0F |
| 0x50038 | E0 CB 02 00 | = 0x0002CBE0 | ROWPIN(0x2CBE0) |

要点：

- 只在 `r5 == 15` 时改写 `E0F`，其余行一律跳过（避免行循环中途清掉 Fn 状态）；
- 返回前恢复 `r1 = ROWPIN`，因为原指令 `ldr r1,[pc,#0x370]` 被覆盖了，后续 `ldrb r2,[r1,r5]` 依赖它；**等价性已逐字节核实**：该 `ldr` 的字面量池槽为 `0x1E858`，其值正是 `0x0002CBE0`（= `ROWPIN`），与 trampoline A 硬编码的常量完全一致，覆盖前后 `r1` 的值不变。补丁脚本启动时会现场复核这一条；
- 蓝牙路径在钩子之后**不再用寄存器 r0 逐位测试**（`0x1E4EC` 会重算 r0），所以清 `local_64[r5]` 的 bit0 就足够了；
- **行循环范围**：`FUN_0001e40c` 的行循环形如 `iVar6 = 0x10; while (iVar5 = iVar6 - 1, iVar6 != 0)`，即 `r5` 依次取 **15…0**（共 16 行），`r5 == 15` 必然被访问到，trampoline A 的触发条件成立。

> **改造前提自检**：r15c0 改成 Fn 之后，Fn 完全依赖该键位被扫描到。蓝牙行掩码 row15 = `0x41`（bit0 = 1，高有效放行 col0）、2.4G 行掩码 row15 = `0xBE`（bit0 = 0，低有效放行 col0）——两条路径下 r15c0 都参与扫描，Fn 可以触发。这两条已加入补丁脚本的**启动时自检**：一旦目标固件的掩码表把 row15 的 bit0 屏蔽，脚本会直接中止并说明「Fn 将永不触发」，而不是打出一个静默失效的补丁。
>

### 5.3　Hook C：2.4G 的 P0.6 判定与伪键注入（@0x411C6）

#### ① 原始代码（patch 前，取自原始固件，18 字节整段替换）

```asm
0x411C6   F7 48         ldr    r0, [pc, #0x3dc]  
0x411C8   00 68         ldr    r0, [r0]          
0x411CA   41 06         lsls   r1, r0, #0x19     
0x411CC   04 D4         bmi    #0x411d8          
0x411CE   01 27         movs   r7, #1            
0x411D0   DF 21         movs   r1, #0xdf         
0x411D2   8D F8 10 10   strb.w r1, [sp, #0x10]   
0x411D6   3D 46         mov    r5, r7            
0x411D8   00 24         movs   r4, #0            
0x411DA   F2 49         ldr    r1, [pc, #0x3c8]  
0x411DC   F2 48         ldr    r0, [pc, #0x3c8]  
0x411DE   0C 31         adds   r1, #0xc          
0x411E0   08 60         str    r0, [r1]
```

2.4G 通道判定 Fn 是否按下的内联代码。`ldr r0,[pc,#0x3dc]` 取 P0.IN 地址，`ldr r0,[r0]` 读 P0.IN 寄存器；`lsls r1,r0,#0x19` 把 bit6(P0.6) 移到符号位；`bmi #0x411d8` 在 P0.6 为高（松开）时跳过 Fn 触发，P0.6 为低（按下）时顺序执行 `movs r7,#1` + `movs r1,#0xdf` + `strb.w r1,[sp,#0x10]` 写入 Fn 伪键码 0xDF。**原始逻辑只认 P0.6，不认矩阵键。**

#### ② Patch 后代码（最终固件 @0x411C6）

```asm
0x411C6   0F F0 1B F8   bl     #0x50200          
0x411CA   00 BF         nop                       
0x411CC   00 BF         nop

0x411D4   00 BF         nop
```

#### ③ 跳转到的 Trampoline C — 2.4G P0.6 判定 / 伪键注入（@0x50200，40 字节）

2.4G P0.6 判定。r7（Fn 保持标志）由 P0.6 改为 **E0F（矩阵 Fn）**，与蓝牙路径统一；伪键由 `0xDF`（伪 Fn）改为 **`0xE0`（伪 Left Ctrl）**。

```asm
0x50208   4F F0 A0 40   mov.w  r0, #0x50000000

0x50210   40 06         lsls   r0, r0, #0x19      ; bit6 → bit31
0x50212   01 D5         bpl    #0x50218          ; P0.6 为低（按下）
0x50214   00 25         movs   r5, #0            ; uVar11 = 0
0x50216   03 E0         b      #0x50220

```

字面量池：

| 地址 | 字节 | 值 | 含义 |

要点：

- `r7`（Fn 保持标志）由 P0.6 改为 **E0F（矩阵 Fn）**，与蓝牙路径统一；
- 伪键由 `0xDF`（伪 Fn）改为 **`0xE0`（伪 Left Ctrl）**。2.4G 的键码数组随后进入报告组装，组装函数按 `0xE0 → 修饰位 bit0` 处理，于是 P0.6 按下时 2.4G 报告带 Left Ctrl；

### 5.4　Hook D：蓝牙扫描里的内联 P0.IN 读（@0x1EB74）

### 5.5　Hook E：蓝牙 HID 报告组装的修饰字节清零（@0x23A76）

#### ① 原始代码（patch 前，取自原始固件）

```asm
0x23A76   00 23         movs   r3, #0            
0x23A78   0B 70         strb   r3, [r1]          ; *param_1 = 0
0x23A7A   CB 71         strb   r3, [r1, #7]      ; param_1[7] = 0
0x23A7C   00 20         movs   r0, #0
```

#### ② Patch 后代码（最终固件 @0x23A76）

```asm
0x23A76   2C F0 C3 FC   bl     #0x50400          
0x23A7A   CB 71         strb   r3, [r1, #7]      ; param_1[7] = 0（未被替换）
0x23A7C   00 20         movs   r0, #0
```

原始 16 进制：00 23 0B 70 CB 71 00 20　→　Patch 后 16 进制：2C F0 C3 FC CB 71 00 20

`0x23A76` 变成 `bl 0x50400`（4 字节，覆盖 `movs r3,#0` + `strb r3,[r1]`）。

#### ③ 跳转到的 Trampoline E — 蓝牙 HID 组装的 Left Ctrl 注入（@0x50400，28 字节）

```asm
0x50400   00 23         movs   r3, #0            
0x50402   0B 70         strb   r3, [r1]          ; *param_1 = 0
0x50404   4F F0 A0 40   mov.w  r0, #0x50000000   
0x50408   D0 F8 10 05   ldr.w  r0, [r0, #0x510]   ; r0 = P0.IN
0x5040C   40 06         lsls   r0, r0, #0x19      ; bit6 → bit31
0x5040E   00 D5         bpl    #0x50412          ; P0.6 为低（按下）
0x50410   01 E0         b      #0x50416          
0x50412   01 23         movs   r3, #1            
0x50414   0B 70         strb   r3, [r1]          ; *param_1 = 1（Left Ctrl 修饰位 bit0）
0x50416   00 23         movs   r3, #0            ; 恢复 r3（后续 strb r3,[r1,#7] 依赖）
0x50418   70 47         bx     lr
```

要点：

- 注入位置选在「修饰字节清零」处，而不是「逐键累加」处：这样无论报告里还有没有别的修饰键，Left Ctrl 位都会被正确置上；
- 返回时 `r3` 必须为 0，因为 `0x23A7A` 的 `strb r3,[r1,#7]`（键码个数）紧随其后且未被替换；
- `FUN_00023a40` 全映像只有一个调用点（`0x23C16`，蓝牙键盘报告流程内），不存在误伤鼠标报告的可能；
- **注入点安全性（复核补记）**：`0x23A78` 之后，`*param_1`（修饰字节）在 `0x23A7A–0x23AF0` 区间内**只有一处**写操作 —— `0x23AE4: strb r3,[r1]`，且其前一条 `0x23AE2: orrs r3, r5` 是 **OR 累加**而非赋值。因此 HOOK_E 注入的 bit0 不会被后续逻辑清掉或整体覆盖。（容易误认的是 `0x23A64: strb r3,[r4]` —— 它写的其实是 `0x20002107` 这个另一个变量，不是 `*param_1`。）

| 开关 | 作用 |
|---|---|
| （默认） | 干跑，只报告不写盘 |
| `--apply` | 实际写盘（自动生成 `.bak` 备份） |
| `--force-mask` | 键盘掩码与预期值不符时，改为按「实际值 + 位操作」强制修补 |
| `--force` | 在 `--force-mask` 基础上，连钩子代码点/键码表条目的字节差异也一并忽略 |

**安全断言分三类**：

| 类别 | 内容 | 不符时 |
|---|---|---|
| 钩子代码点 + 键码表条目 | HOOK_A/B/C/D/E 的原始字节、4 个键码表字节 | 默认中止；`--force` 可放行 |
| 字面量池槽 | `0x1B8A0` 必须是 `0x20001E0F` | **硬中止**，不可放行 |
| 键盘掩码 | `0x1E84C`、`0x4A6B2` | 默认中止；`--force-mask` / `--force` 可放行 |

掩码强制修补的关键语义：**不套用原版常量**，而是按「实际值 + 位操作」推出目标值（蓝牙 `| bit4`、2.4G `& ~bit4`），因此变体固件掩码表的其余位不会被覆盖。

### 6.1　强制修补时的输出提示

掩码不符且未加开关时，脚本**先给出预览再中止**，便于判断是否该放行：

```asm
  !! 键盘掩码与预期值不符（2 处），已中止。
     0x01E84C  期望 E7 实际 E3
     0x04A6B2  期望 1C 实际 10
     若这属于同型号的变体固件（掩码表取值不同、语义相同），
     可加 --force-mask 忽略差异：补丁将按「实际值 + 位操作」强制修补——
       0x01E84C  实际 0xE3 -> 强制写入 0xF3（置 bit4，其余位保留）
       0x04A6B2  实际 0x10 -> 强制写入 0x00（清 bit4，其余位保留）
     不会套用原版常量，因此变体固件掩码表的其余位不会被覆盖。
```

### 6.2　掩码强制修补的关键语义：不套用原版常量

掩码目标值**不是**写死 `0xF7` / `0x0C`，而是由**实际值**按位推出（与 v5 同一套语义）：

| 掩码点 | 位操作 | 公式 | 原版（实际 = 预期） | 变体示例 |
|---|---|---|---|---|
| 蓝牙 `0x1E84C`（高有效 `& mask`） | 置 bit4 | `实际 \| 0x10` | `0xE7 → 0xF7` | `0xE3 → 0xF3`（其余位保留 E3） |
| 2.4G `0x4A6B2`（低有效 `& ~mask`） | 清 bit4 | `实际 & ~0x10` | `0x1C → 0x0C` | `0x10 → 0x00` |

这样做的意义：变体固件的掩码表若在**其它位**上与本版本不同，套用原版常量会把那些位一并改错；而按位操作只动 bit4（col4 / ASD 列），其它位原样保留。

**v6 特有的补充约束**：掩码位操作只保证「放行 r12c4」这一条；**r15c0 必须同时被放行**，否则矩阵 Fn 永不触发。因此补丁脚本在启动时对两张表的 **row15 bit0** 另做一次放行性检查（见 5.1 节末「改造前提自检」与第十一章）。

## 八、已知限制与风险

1. **P0.6 的去抖在 v6 中不再用于 Ctrl 注入**。

由于 `E0F` 被整体换源，`FUN_00020bd8` 里「P0.6 松开 && E0F==1」的边沿判定随之失效，P0.6 的去抖状态机（写入 `E0F2`）不再被可靠地「武装」。因此 Ctrl 注入统一采用**原始 `P0.IN` bit6**——这与原固件在 2.4G 路径（HOOK_C）和蓝牙扫描内联处（HOOK_D 改造前）对 P0.6 的用法一致。代价：P0.6 的电气抖动理论上会造成极短暂的 Ctrl 按下/抬起。若实机发现抖动明显，可改为读 `E0F2`（但需同时修好 `FUN_00020bd8` 的边沿判定，见下文「可选加固」）。

2. **2.4G 路径的 Fn 门控已整体换成矩阵 Fn**（复核更正）。

2.4G 扫描函数用寄存器 `r7` 作为 Fn 门控：`0x41286: cbz r7, #0x412ca`（`r7 == 0` → 跳过 Fn 映射分支）与 `0x413D0: cbz r7, #0x41422`（同类）。原固件里 `r7` 仅由 `0x411CE: movs r7,#1`（P0.6 按下）置位，本改造把该来源换成 `E0F`（矩阵 r15c0）。`r7` 在 `0x41526` / `0x416A4` 之后被复用为循环变量，与 `0x411C6` 的写入点不冲突，替换是安全的。

3. **蓝牙与 2.4G 两条路径共用 `E0F`**。

正常情况下同一时刻只有一条协议在跑，扫描函数不会互相覆盖；若固件存在两种协议同时扫描的路径，需要把 `E0F` 拆成两个变量。

4. **无实机验证条件**。

本次改造的全部结论来自**静态分析 + 反汇编复核 + 行为仿真**，没有实机刷写验证。请在有回滚手段（`.bak` 备份 / 原始固件）的前提下上机测试。

5. **Fn 层键码表未被改动 —— r12c4 的 Left Ctrl 只在「非 Fn 层」生效**（复核补记）。

固件的 Fn 层键码表在 `0x2CC78`（128 字节，按 `idx = row*8+col` 索引，池槽 `0x020B48` 指向它），本补丁只改了**主表** `0x2CBF0` / `0x4A6FA`，**没有动 Fn 层表**。该表 `idx100 (r12c4) = 0x1C`、`idx120 (r15c0) = 0xC1` 保持原样。影响：按住 Fn（现在 = r15c0）时再按 r12c4，走的是 Fn 层重映射（`0x1C`），**不是** Left Ctrl；只有**不按 Fn** 时 r12c4 才是 Left Ctrl。这与原固件的行为差异为零（原固件 r12c4 本身就是空槽，Fn 层同样给 `0x1C`），但使用时应注意：**Left Ctrl 与 Fn 不可同时使用**。

### 可选加固（若实机发现 P0.6 抖动）

让 `FUN_00020bd8` 的「P0.6 松开 && E0F==1」判定改读 `E0F2`，即可让 P0.6 的去抖重新可靠工作，随后把两处 Ctrl 注入改为读 `E0F2`：

- `0x020FD4` 池槽：`0x20001E0F` → `0x20004800`（`E0F2`）；
- 但这样 `2109 = E0F && D7B` 就会用 `E0F2`（P0.6）计算，**P0.6 又会变回 Fn**，因此还需要把 `FUN_00020bd8` 中 `0x20C0C` 那条 `ldr r0,[pc,#0x3C4]` 改指到另一个装 `0x20001E0F` 的池槽（该函数字面量池 `0x20FC0-0x20FCC` 有 4 个 0 引用槽可利用）。

## 九、踩坑与逐步确认（正确性保障）

### 9.1　历次版本的关键发现（均已规避 / 修正）

| 项目 | 值 |
|---|---|
| 2.4G 路径缺陷（v5 原始版盲区，v5.1 已修，v6 沿用） | v5 **原始版**的 Trampoline B 只清 `local_84[r4]`、未复原 `0x4125E` 的 Z 位（该缺陷已由 v5.1 修订记录更正，v6 沿用修好后的结构）。2.4G 路径钩子之后**逐位测试用的是寄存器 r0**（`0x4126C: tst.w r0, ip`），且 `beq` 依赖 `0x4124C bics` 的 Z。v6 已同时清 `r0` 与数组、并在返回前 `cmp r0,#0` 复原 Z。 |
| Fn 层表占用 | 本版不把 r12c4 写成某个伪键码再用伪键覆盖，而是直接清行位图 bit0（2.4G 侧也清 r0），键码表保持为 0x00，避免污染。 |
| 空洞违规 | 5 个 trampoline 全部落在 `0x50000-0x60000`，经静态可达性分析确认该区静态不可达、全为擦除态。 |
| RAM 选址误报（v5 早期文档错误，v6 沿用更正后结论） | 早期版本写的「最高到 `0x20004138`（654 个地址）」是宽松扫描把落在指令中间的半字误当成 ldr 造成的误报；按函数边界精确普查为 **661 个地址、最高 `0x20003928`**。`E0F2@0x20004800` 距真实最高引用仍有余量 3616 字节。 |
| 钩子点字节误读（v6 复核更正） | 蓝牙扫描内联 `cbnz r2,#...`（HOOK_D 之后）的实际目标是 `0x1EBBC`（原早期稿误写作 `0x1EBC`，缺中间 B）。本文档已按反汇编逐一更正。 |

### 9.2　逐步确认的关键点

1. **关键常量必须取自原始固件实测**：ROWPIN(0x2CBE0)、E0F(0x20001E0F)、P0.IN(0x50000510) 的目标地址，均通过读取原指令的 pc 相对字面量池逐一核对，而非凭记忆。所有 ASM 行的二进制数值均由本说明配套的提取脚本从 `KC-1957_88_v6.bin` 逐字节读出。
2. **寄存器契约核对**：BT 调用点 `r0=local_64[r5]`、2.4G 调用点 `r0=local_84[r4]`，均在 `bl` 之前成立（重算 `r0` 发生在调用点之后），故 trampoline 内 `tst r0,#1` 检测的就是 r15c0；返回前精确复原被覆盖的 `r1`（BT）或 `r2`（2.4G）。
3. **RAM 选址安全**：按函数边界精确普查 2434 个函数实测，全映像 pc 相对字面量引用的 RAM 变量共 **661 个**，最高只到 `0x20003928`，其上零引用；`E0F2@0x20004800` 取最高引用 +3616 字节，既避开数组延伸风险，又距 RAM 顶端仍有约 28KB。补丁脚本启动时会现场复核 `0x20004800-0x20004900` 窗口内引用数为 0。
4. **并行路径隔离**：BT 子树与 2.4G 子树零交集；`2109/D7B` 为 BT 专属，2.4G 用自身标志 `r7` 驱动，互不干扰。
5. **新变量唯一性**：二进制扫描确认 trampoline 区常量集仅含 `E0F / E0F2 / P0.IN / ROWPIN`，**绝不出现 0x20002109 / 0x20001D7B / 0x20001E09**。

### 9.3　最终独立复核

对 `KC-1957_88_orig.bin ↔ KC-1957_88_v6.bin` 做逐项断言，**87 项全部通过**（A–F 共 77 项 + G 组 10 项）：

| 复核项 | 结论 | 依据 |
|---|---|---|
| 改动范围 | 274 字节 / 18 区域，无越界 | 所有改动必须落在允许清单内，脚本逐字节比对 |
| 向量表 / 固件长度 | Reset_Handler 不变，长度仍为 512 KB | 向量表首 8 字节与长度断言 |
| 两张键码表 | idx100 → `0xE0`、idx120 → `0x00`，其余 124 项零改动 | 逐字节 diff |
| 两张行掩码表 | 仅翻转 r12 的 bit4；**row15 的 bit0 未动** | 逐字节 diff |
| 字面量池槽 | `0x1B8A0` → `E0F2`；其余 5 个「读 E0F」池槽**仍指向 E0F** | 解析全部 pc 相对加载的常量序列 |
| HOOK_A 覆盖的 `ldr` | 池槽 `0x1E858` 的值 == `ROWPIN(0x2CBE0)` | 覆盖前后 `r1` 等价；且已加入脚本启动自检 |
| HOOK_E 注入点安全性 | `0x23A7A–0x23AF0` 内 `*param_1` 只有 `0x23AE4` 一处写，且为 **OR 累加** | 注入的 bit0 不会被后续逻辑清掉或整体覆盖 |
| 钩子之后的关键指令 | `strb r3,[r1,#7]` / `cbnz r2` / `ldrb r2,[r1,r5]` / `lsl.w r1,r8,r2` 全部完好 | 逐条反汇编核对 |
| Trampoline 行为仿真 | 14 条行为断言全部通过（含 2.4G 的 Z 位复原、r0 的 bit0 清除） | 最小 Thumb 解释器**逐条执行** |
| Fn 层键码表 | `0x2CC78` 未被改动 | Fn 层映射维持原固件行为 |
| Trampoline 区常量集 | 仅 `E0F / E0F2 / P0.IN / ROWPIN` | 不出现 `0x20002109 / 0x20001D7B / 0x20001E09` 等变量 |

> **结论：**补丁严格限定为「Fn 判定源整体换成矩阵 r15c0，P0.6 与 r12c4 改为发 Left Ctrl」，除新增变量 `E0F2` 外，**14 处读取 E0F 的代码与全部修饰位转译通路均自动跟随、未引入新逻辑**；全部结论来自静态分析与行为仿真，**无实机刷写验证**。
>

## 十一、v6 修订与审计记录

> **背景：**v6 在原始固件上独立打补丁，同时把 v5 的 Fn 机制逐条拆开重新验证了一遍 —— 结果发现 v5 **原始版**的 Trampoline B（2.4G 行循环）有两处实质缺陷，这两处都是 v5 自身的推理盲区，直到逐指令核对 2.4G 路径才暴露出来。
>
> v5 随后以 **v5.1** 修订了这两处缺陷（见 v5 文档「v5.1 修订记录」章）。本章记录 **v6 相对 v5.1 的逐字节差异**与本版新增的审计手段，并更正一处对 v5 版本的表述。
>

### 11.1　Trampoline B：与 v5.1 **结构同构**，仅 8 字节不同

v6 的 Trampoline B（`@0x50100`，64 字节）与 v5.1 的同名 trampoline **逐字节比对**，64 字节中**仅 8 字节不同**，其余 56 字节完全相同。差异全部来自「语义换轨」而非结构改动：

| 偏移 | v5.1 字节 | v6 字节 | 含义 |
|---|---|---|---|
| `0x50100` | 0C 2C | 0F 2C | `cmp r4,#12` → `cmp r4,#15`（矩阵行由 12 改为 15） |
| `0x50106` | 10 0F | 01 0F | `tst.w r0,#0x10` → `tst.w r0,#1`（检测位由 bit4 改为 bit0） |
| `0x50114` | 10 00 | 01 00 | `bic r0,r0,#0x10` → `bic r0,r0,#1` |
| `0x5011E` | 10 02 | 01 02 | `bic r2,r2,#0x10` → `bic r2,r2,#1`（清数组中的同一 bit） |
| `0x50138` | 00 48 00 20 | 0F 1E 00 20 | 字面量池：`FN_MATRIX(0x20004800)` → `E0F(0x20001E0F)` |
| `0x5013C` | 00 48 00 20 | 0F 1E 00 20 | 字面量池：同上 |

而**v5.1 的两处关键修正字节，v6 原样继承、一字未改**——这正是 v6 不必再单独踩坑的原因：

| 偏移 | v5.1 与 v6 完全相同的字节 | 作用 |
|---|---|---|
| `0x50112` | 20 F0 xx 00 | `bic r0, r0, #N` —— 清理**寄存器 r0**（2.4G 路径钩子之后的逐位测试用的就是 r0，不是数组） |
| `0x50132` | 00 28 | `cmp r0, #0` —— 复原 `0x4125E` 的 `beq` 所依赖的 Z 位（源自 `0x4124C` 的 `bics`） |

> **沿革小结：**v5 **原始版**只清 `local_84[r4]`、且未复原 Z 位（→ 2.4G 路径根本没屏蔽住目标键、且第 12 行其它按键可能被整行丢弃）→ **v5.1** 用上表两条指令修好 → **v6** 直接沿用修好后的结构，只把行号（12→15）、检测位（bit4→bit0）、写入目标（`FN_MATRIX`→`E0F`）换成本版语义。
>

### 11.2　Trampoline A / C / D：属**语义替换**，非缺陷修正

| Trampoline | v5.1（Fn 矩阵化） | v6（Ctrl/Fn 互换） | 差异字节 |
|---|---|---|---|
| A @0x50000（60 B） | 写 `FN_MATRIX=1` + 强制 `E0F=1`（与 P0.6 **并联**）+ 清 `local_64[12]` bit4 | 写 `E0F=1`（**整体换源**）+ 清 `local_64[15]` bit0 | 43 / 60 |
| C @0x50200（40 B） | Fn 判定 OR：P0.6 低 **或** `FN_MATRIX` → 写伪键 `0xDF` | `r7 = E0F`（矩阵 Fn 作 2.4G 门控）+ P0.6 低 → 写伪键 `0xE0` | 24 / 40 |
| D @0x50300（24 B） | 保护 `E0F` 的去抖清除不被 `FN_MATRIX` 路径打断 | 蓝牙扫描内联读：`P0.IN` bit6 → **改读 `E0F`** | 19 / 24 |
| E @0x50400（28 B） | —（该区在 v5.1 中为擦除态 `0xFF`） | BT HID 组装处注入 Left Ctrl 修饰位 | 28 / 28（**v6 新增**） |

需要强调的是：C / D 的改动**不是**「修 bug」，而是「换语义」——v6 的 Fn 判定源整体从 P0.6 迁到矩阵 r15c0，这两条路径的取值来源必须随之改变。

### 11.3　v6 新增①：补丁脚本的**启动时自检**

v5 的补丁脚本没有启动自检；v6 新增两项，任一不满足即**直接中止**，而不是打出一个静默失效的固件：

| 自检项 | 检查内容 | 不满足时的后果 |
|---|---|---|
| ROWPIN 池槽一致性 | HOOK_A 覆盖掉的那条 `ldr r1,[pc,#imm]`，其字面量池槽 `0x1E858` 的值必须 == `ROWPIN(0x2CBE0)` | 中止：否则 trampoline 还原的 `r1` 与原始指令不等价，后续 `ldrb r2,[r1,r5]` 会读到错误地址 |
| row15 的 bit0 放行 | 蓝牙行掩码 row15 的 bit0 必须为 1（高有效放行 col0）、2.4G 行掩码 row15 的 bit0 必须为 0（低有效放行 col0） | 中止并提示「**Fn 将永不触发**」 |

### 11.4　v6 新增②：G 组「改造前提交叉验证」

验证脚本新增 **G 组 10 项**，全部是对**改造前固件**的前提性交叉验证——即「如果这些前提不成立，补丁就不该被认为正确」：

1. 蓝牙 / 2.4G 行掩码 row15 的 bit0 状态（保证 r15c0 参与扫描）；
2. HOOK_A 覆盖的 `ldr` 池槽值 == `ROWPIN`；
3. `*param_1` 在 `0x23A7A–0x23AF0` 内只有 `0x23AE4` 一处写且为 OR 累加（HOOK_E 注入不被覆盖）；
4. HOOK_C 之后的 `0x411D8 movs r4,#0` 完好；
5. HOOK_D 之后的 `0x1EB8A` 条件分支完好；
6. Fn 层键码表 `0x2CC78` 未被改动。

### 11.5　改动范围与验证

- 与 v5.1 相比：**改动集中在 Trampoline A / C / D（语义换轨）与新增的 Trampoline E**；Trampoline B 仅 8 字节不同（见 11.1）。
- 与原始固件相比：改动 **274 字节 / 18 区域**。
- 验证：`verify_v6.py` 独立脚本 **87 项全部通过**；其中 E 组用最小 Thumb 解释器**逐条执行** 5 个 trampoline 做行为仿真，G 组做 10 项前提交叉验证。
- 补丁脚本 `fn_swap_patch.py` 全部自检通过：代码区完整解码、字面量池常量序列、`imm12` 回填、RAM 选址窗口复核、语义自洽检查、ROWPIN 池槽、row15 bit0 放行。

### 11.6　顺带更正的一处**对 v5 版本的表述**

本文档 5.2 节与 9.1 节此前把「2.4G 路径未清 r0 的 bit0、未复原标志位」记在「**v5** 的 Trampoline B」名下。经与 `KC-1957_88_fn7_v51.bin` 逐字节核对，准确表述应为：

- 该缺陷存在于 **v5 原始版**；
- **v5.1 已修正**（v5 文档「v5.1 修订记录」章即记这两件事）；
- **v6 沿用 v5.1 修好后的结构**，只把行号、检测位与写入目标换成本版语义（详见 11.1）。

结论不变（v6 的 2.4G 路径两处均正确），仅归属表述更精确。
